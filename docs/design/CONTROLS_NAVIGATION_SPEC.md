# Kontrol dan navigasi MTC Inventory

Arahan pemilik 31 Oktober 2026 memperluas perbaikan tombol/input ke halaman lain dan menambahkan Kembali untuk PWA mobile. Empat screenshot pengguna menjadi anti-reference. Ini refinement dalam DESIGN.md, bukan pergantian brand atau proses inventory.

- Kembali: bar navigasi terpisah di bawah header/logo, sticky mobile dengan safe area, teks/ikon pada desktop. Memakai router.back hanya untuk entry yang diamati dalam sesi UI aplikasi. Tidak menyimpulkan keamanan dari history.length. Marker history mempertahankan state Next; tidak membaca/mengubah sesi autentikasi. Riwayat filter/halaman dipertahankan oleh browser/router. Reload, entry langsung dan entry tidak dikenal memakai fallback role/modul dengan replace, sehingga tidak membuat loop kembali ke detail atau keluar ke situs lain. Home tidak memakai tombol Kembali.
- Kontrol konsisten: boundary input/secondary button minimal 3:1 terhadap putih, teks input/select 16px, target utama minimal 44px. Select tunggal tetap native dengan chevron seragam; file picker tetap native. Readonly dan disabled dibedakan; focus ring dan reduced motion dipertahankan.
- Hierarki/ikon: edit memakai Pencil, permintaan memakai Hand/Send, tambah Plus, simpan Save, konfirmasi Check, transfer ArrowLeftRight dan QR memakai QrCode/ScanLine. Aksi pembatalan/penolakan diberi tone danger. Detail barang mempunyai satu aksi primer; edit/penerimaan pendukung dan aksi tabel memakai secondary/quiet. Kelola lokasi serta Pindai QR terlihat sebagai kontrol yang dapat dipakai. Teks satuan stok tidak mewarisi letter spacing angka besar.
- Transfer: pilihan barang dapat dicari. Unit berupa checkbox native, pencarian dan jumlah terpilih; hanya unit barang/lokasi asal yang dipilih ditampilkan, sesuai eligibility existing available/blocked. Mengganti barang/lokasi menghapus pilihan lama. Serialized menghitung jumlah otomatis dan mengunci input jumlah; quantity tetap manual mengikuti satuan. Setelah sukses, pilihan unit dan pencarian dibersihkan. Enter pada pencarian unit tidak mem-posting form.
- Tidak menambah dependency, schema, endpoint, saldo pembukaan atau izin. Unit serialized tetap diperbarui per identitas; tidak membuat Balance quantity kedua. Semua posting, alasan, retry, audit, eligibility dan freeze tetap divalidasi service server existing.

Bukti wajib: Back berturut-turut, forward, filter, reload/entry langsung dan riwayat eksternal; transfer pilihan ganda, filter/search, reset konteks dan jumlah, posting serta reset sukses; kontrol role dan lebar 320-1440. Halaman sampel mencakup katalog, detail/edit, Master Data, penerimaan, request, loan, transfer, QR, laporan dan profil. Capture desktop/mobile serta status CI/deploy dicatat pada STATUS_IMPLEMENTASI.md. Tidak mengklaim uji perangkat atau screen reader nyata.
